### USER
我有一个计算逻辑，需要很多步骤，我想可视化这些步骤，并且节点之间可以调整 ，每个节点都有输入数据，计算，输出数据等。节点输入数据可以来源不同比如上一个节点输出，json excel 等。可以多个节点输出作为一个节点输入，或者一个节点可以有多个输出 我用springboot 3 vue3 jdk21 。

# 一、整体架构设计

你可以把系统拆成两部分：

## 1. 前端可视化编辑器

负责：

- 展示节点
- 拖拽节点
- 连线
- 配置节点参数
- 查看输入数据
- 查看输出数据
- 执行流程
- 显示执行状态

建议使用：

- Vue3
- TypeScript
- Pinia
- Element Plus / Ant Design Vue
- 图编辑库：
  - Vue Flow
  - AntV X6
  - LogicFlow
  - jsPlumb
  - Rete.js

其中我比较推荐：

> **Vue Flow**：如果你想要轻量、现代、和 Vue3 集成好  
> **AntV X6**：如果你想要功能强、企业级、扩展能力强  
> **LogicFlow**：如果你偏业务流程、审批流、规则流

你这个是计算流，我更推荐：

- 小型项目：Vue Flow
- 中大型项目：AntV X6

---

## 2. 后端计算引擎

负责：

- 保存流程图结构
- 解析节点和连线
- 校验 DAG 是否合法
- 拓扑排序
- 执行节点
- 管理上下文数据
- 处理数据源输入
- 输出结果
- 日志追踪
- 错误处理

后端核心概念：

> 一个流程 = 一组节点 + 一组连线  
> 每个节点 = 输入 + 计算逻辑 + 输出  
> 节点之间通过连线传递数据

# 二、核心概念设计

你可以把整个系统抽象成下面几个对象。

## 1. 流程图 Flow

表示一整个计算流程。

```json
{
  "flowId": "flow_001",
  "name": "销售计算流程",
  "nodes": [],
  "edges": []
}
```

---

## 2. 节点 Node

每个节点表示一个计算步骤。

```json
{
  "id": "node_1",
  "type": "CALCULATE",
  "name": "计算总价",
  "config": {},
  "inputs": [],
  "outputs": []
}
```

节点类型可以包括：

| 节点类型 | 说明 |
|---|---|
| INPUT_JSON | JSON 输入 |
| INPUT_EXCEL | Excel 输入 |
| INPUT_MANUAL | 手工输入 |
| INPUT_API | 接口输入 |
| CALCULATE | 计算节点 |
| SCRIPT | 脚本节点 |
| FILTER | 过滤节点 |
| MERGE | 合并节点 |
| SPLIT | 拆分节点 |
| OUTPUT | 输出节点 |
| CONDITION | 条件节点 |

---

## 3. 连线 Edge

表示节点之间的数据流向。

```json
{
  "id": "edge_1",
  "sourceNodeId": "node_1",
  "sourcePort": "output_total",
  "targetNodeId": "node_2",
  "targetPort": "input_total"
}
```

这里建议一定要引入「端口」概念。

因为你有：

- 一个节点多个输出
- 一个节点多个输入
- 多个节点输出作为同一个节点输入

所以不能简单写成：

```json
sourceNodeId -> targetNodeId
```

而应该是：

```text
sourceNodeId.sourcePort -> targetNodeId.targetPort
```

# 五、多输入、多输出设计

你的需求里有：

> 多个节点输出作为一个节点输入

这可以分成两种情况。

---

## 情况一：一个输入端口接收多个上游输出

例如合并节点：

```text
节点A输出 -> 合并节点 inputs
节点B输出 -> 合并节点 inputs
节点C输出 -> 合并节点 inputs
```

这时目标节点输入可以设计为数组：

```json
{
  "inputCode": "dataList",
  "multi": true,
  "dataType": "ARRAY"
}
```

运行时：

```json
{
  "dataList": [
    {
      "fromNodeId": "node_a",
      "value": {}
    },
    {
      "fromNodeId": "node_b",
      "value": {}
    }
  ]
}
```

或者更简单：

```json
{
  "dataList": [
    {},
    {},
    {}
  ]
}
```

---

## 情况二：一个节点有多个输入端口

例如：

```text
订单节点 -> 订单数据
库存节点 -> 库存数据
价格节点 -> 价格数据
```

计算节点：

```json
{
  "inputPorts": [
    {
      "code": "orderData",
      "dataType": "OBJECT"
    },
    {
      "code": "stockData",
      "dataType": "OBJECT"
    },
    {
      "code": "priceData",
      "dataType": "OBJECT"
    }
  ]
}
```

这种更常见，也更清晰。

我建议你优先采用：

> 一个节点有多个输入端口，而不是一个输入端口接收所有数据。

如果确实需要聚合，再提供专门的 `MERGE` 节点。

---

## 多输出

一个节点可以有多个输出端口。

例如：

```json
{
  "outputPorts": [
    {
      "code": "successData",
      "name": "成功数据"
    },
    {
      "code": "failedData",
      "name": "失败数据"
    },
    {
      "code": "summary",
      "name": "汇总结果"
    }
  ]
}
```

后续连线：

```text
node_1.successData -> node_2.input
node_1.failedData -> node_3.input
node_1.summary -> node_4.input
```

# 六、流程执行引擎设计

后端最重要的是执行引擎。

你的流程本质上最好限制为 **DAG 有向无环图**。

也就是：

```text
节点之间不能有循环依赖
```

如果允许循环，会复杂很多。建议第一版只做 DAG。

---

## 执行步骤

```text
1. 加载流程图
2. 校验节点和连线
3. 检查是否有环
4. 拓扑排序
5. 初始化执行上下文
6. 按顺序执行节点
7. 每个节点执行前解析输入
8. 节点计算
9. 节点输出写入上下文
10. 记录执行日志
11. 返回最终结果
```

---

# 七、执行上下文 Context

节点之间传递数据不要直接传，而是通过执行上下文。

例如：

```java
Map<String, NodeOutput> executionContext
```

结构可以是：

```json
{
  "node_1": {
    "totalAmount": 1000,
    "detail": {}
  },
  "node_2": {
    "finalResult": 900
  }
}
```

这样后续节点可以通过：

```text
node_1.totalAmount
```

获取上游输出。

## 2. 节点执行上下文

```java
public class NodeExecutionContext {

    private final String executionId;
    private final NodeDefinition node;
    private final Map<String, Object> inputs;
    private final Map<String, Object> globalContext;

    public NodeExecutionContext(
            String executionId,
            NodeDefinition node,
            Map<String, Object> inputs,
            Map<String, Object> globalContext
    ) {
        this.executionId = executionId;
        this.node = node;
        this.inputs = inputs;
        this.globalContext = globalContext;
    }

    public String getExecutionId() {
        return executionId;
    }

    public NodeDefinition getNode() {
        return node;
    }

    public Map<String, Object> getInputs() {
        return inputs;
    }

    public Map<String, Object> getGlobalContext() {
        return globalContext;
    }
}
```

## 3. 节点执行结果

```java
public record NodeResult(

        return new NodeResult(NodeStatus.SUCCESS, outputs, null);

    public static NodeResult fail(String errorMessage) {
        return new NodeResult(NodeStatus.FAILED, Map.of(), errorMessage);
```

# 十三、节点执行器示例

## 1. 计算节点执行器

```java
@Component
public class CalculateNodeExecutor implements NodeExecutor {

    @Override
    public String supportType() {
        return "CALCULATE";
    }

    @Override
    public NodeResult execute(NodeExecutionContext context) {
        try {
            Object price = context.getInputs().get("price");
            Object quantity = context.getInputs().get("quantity");

            double p = Double.parseDouble(price.toString());
            double q = Double.parseDouble(quantity.toString());

            double total = p * q;

            Map<String, Object> outputs = new HashMap<>();
            outputs.put("totalAmount", total);

            return NodeResult.success(outputs);
        } catch (Exception e) {
            return NodeResult.fail(e.getMessage());
        }
    }
}
```

## 3. 简单执行引擎实现

```java
@Service
public class DefaultFlowEngine implements FlowEngine {

    private final Map<String, NodeExecutor> executorMap = new HashMap<>();

    public DefaultFlowEngine(List<NodeExecutor> executors) {
        for (NodeExecutor executor : executors) {
            executorMap.put(executor.supportType(), executor);
        }
    }

    @Override
    public FlowExecutionResult execute(FlowDefinition flow) {
        String executionId = UUID.randomUUID().toString();

        try {
            List<NodeDefinition> sortedNodes = topologicalSort(flow);

            Map<String, Map<String, Object>> context = new HashMap<>();
            Map<String, NodeResult> nodeResults = new HashMap<>();

            for (NodeDefinition node : sortedNodes) {
                Map<String, Object> inputs = resolveInputs(flow, node, context);

                NodeExecutionContext nodeContext = new NodeExecutionContext(
                        executionId,
                        node,
                        inputs,
                        Map.of()
                );

                NodeExecutor executor = executorMap.get(node.type());

                if (executor == null) {
                    throw new IllegalStateException("找不到节点执行器: " + node.type());
                }

                NodeResult result = executor.execute(nodeContext);
                nodeResults.put(node.id(), result);

                if (result.status() == NodeStatus.FAILED) {
                    return new FlowExecutionResult(
                            executionId,
                            FlowStatus.FAILED,
                            nodeResults,
                            result.errorMessage()
                    );
                }

                context.put(node.id(), result.outputs());
            }

            return new FlowExecutionResult(
                    executionId,
                    FlowStatus.SUCCESS,
                    nodeResults,
                    null
            );

        } catch (Exception e) {
            return new FlowExecutionResult(
                    executionId,
                    FlowStatus.FAILED,
                    Map.of(),
                    e.getMessage()
            );
        }
    }
}
```

# 十五、输入解析逻辑

这里处理「节点输入来自哪里」。

---

## 输入解析逻辑

```java
private Map<String, Object> resolveInputs(
        FlowDefinition flow,
        NodeDefinition node,
        Map<String, Map<String, Object>> context
) {
    Map<String, Object> inputs = new HashMap<>();

    for (EdgeDefinition edge : flow.edges()) {
        if (edge.targetNodeId().equals(node.id())) {
            String sourceNodeId = edge.sourceNodeId();
            String sourcePort = edge.sourcePort();
            String targetPort = edge.targetPort();

            Map<String, Object> sourceOutputs = context.get(sourceNodeId);

            if (sourceOutputs != null) {
                Object value = sourceOutputs.get(sourcePort);

                InputPort inputPort = node.inputPorts()
                        .stream()
                        .filter(x -> x.code().equals(targetPort))
                        .findFirst()
                        .orElse(null);

                if (inputPort != null && inputPort.multi()) {
                    Object current = inputs.get(targetPort);

                    List<Object> list;

                    if (current instanceof List) {
                        list = (List<Object>) current;
                    } else {
                        list = new ArrayList<>();
                    }

                    list.add(value);
                    inputs.put(targetPort, list);
                } else {
                    inputs.put(targetPort, value);
                }
            }
        }
    }

    return inputs;
}
```

这样你就可以支持：

```text
一个输入端口接收单个值
一个输入端口接收多个值
多个上游节点输出给同一个节点
```

# 十六、拓扑排序实现

DAG 执行必须做拓扑排序。

简单实现：

```java
private List<NodeDefinition> topologicalSort(FlowDefinition flow) {
    Map<String, Integer> inDegree = new HashMap<>();
    Map<String, List<String>> graph = new HashMap<>();
    Map<String, NodeDefinition> nodeMap = new HashMap<>();

    for (NodeDefinition node : flow.nodes()) {
        nodeMap.put(node.id(), node);
        inDegree.put(node.id(), 0);
        graph.put(node.id(), new ArrayList<>());
    }

    for (EdgeDefinition edge : flow.edges()) {
        graph.get(edge.sourceNodeId()).add(edge.targetNodeId());
        inDegree.put(
                edge.targetNodeId(),
                inDegree.get(edge.targetNodeId()) + 1
        );
    }

    Queue<String> queue = new LinkedList<>();

    for (Map.Entry<String, Integer> entry : inDegree.entrySet()) {
        if (entry.getValue() == 0) {
            queue.offer(entry.getKey());
        }
    }

    List<NodeDefinition> result = new ArrayList<>();

    while (!queue.isEmpty()) {
        String nodeId = queue.poll();
        result.add(nodeMap.get(nodeId));

        for (String next : graph.get(nodeId)) {
            inDegree.put(next, inDegree.get(next) - 1);

            if (inDegree.get(next) == 0) {
                queue.offer(next);
            }
        }
    }

    if (result.size() != flow.nodes().size()) {
        throw new IllegalStateException("流程存在循环依赖");
    }

    return result;
}
```

# 二十九、并行执行设计

当多个节点没有依赖关系时，可以并行执行。

例如：

```text
节点A、节点B、节点C 都只依赖输入节点
```

可以并行。

实现方式：

```text
按拓扑层级执行
同一层级无依赖节点并行
下一层级等待上一层级完成
```

示例：

```text
Level 1: 输入节点
Level 2: 节点A、节点B、节点C
Level 3: 汇总节点
```

第一版可以先串行执行。

第二版再做并行。

# 三十三、核心设计原则

最后给你几个非常重要的设计原则。

## 1. 一定用「端口」而不是简单节点连线



因为你有多输入多输出。


前端保存的是画布结构：

```json

viewport
style
```

后端执行需要领域模型：

```json

```

最好中间做一层转换。

不要一上来支持：


## 4. `DefaultFlowEngine.java`

这是核心执行引擎。

它负责：

- 拓扑排序
- 按顺序执行节点
- 解析上游节点输出
- 将结果写入上下文
- 返回每个节点执行结果

```java
package com.example.flowdemo.engine;

import com.example.flowdemo.model.EdgeDefinition;
import com.example.flowdemo.model.FlowDefinition;
import com.example.flowdemo.model.FlowExecutionResult;
import com.example.flowdemo.model.FlowStatus;
import com.example.flowdemo.model.InputPort;
import com.example.flowdemo.model.NodeDefinition;
import com.example.flowdemo.model.NodeResult;
import com.example.flowdemo.model.NodeStatus;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.LinkedList;
import java.util.List;
import java.util.Map;
import java.util.Objects;
import java.util.Queue;
import java.util.UUID;

@Service
public class DefaultFlowEngine implements FlowEngine {

    private final Map<String, NodeExecutor> executorMap = new HashMap<>();

    public DefaultFlowEngine(List<NodeExecutor> executors) {
        for (NodeExecutor executor : executors) {
            executorMap.put(executor.supportType(), executor);
        }
    }

    @Override
    public FlowExecutionResult execute(FlowDefinition flow) {
        String executionId = UUID.randomUUID().toString();
        Map<String, NodeResult> nodeResults = new LinkedHashMap<>();

        try {
            List<NodeDefinition> nodes = safeNodes(flow);
            List<EdgeDefinition> edges = safeEdges(flow);

            List<NodeDefinition> sortedNodes = topologicalSort(nodes, edges);

            Map<String, Map<String, Object>> context = new HashMap<>();

            for (NodeDefinition node : sortedNodes) {
                NodeExecutor executor = executorMap.get(node.type());

                if (executor == null) {
                    throw new IllegalStateException("找不到节点执行器: " + node.type());
                }

                Map<String, Object> inputs = resolveInputs(node, edges, context);

                NodeExecutionContext nodeContext = new NodeExecutionContext(
                        executionId,
                        node,
                        inputs,
                        Map.of()
                );

                NodeResult result = executor.execute(nodeContext);
                nodeResults.put(node.id(), result);

                if (result.status() != NodeStatus.SUCCESS) {
                    return new FlowExecutionResult(
                            executionId,
                            FlowStatus.FAILED,
                            nodeResults,
                            result.errorMessage()
                    );
                }

                context.put(
                        node.id(),
                        result.outputs() == null ? Map.of() : result.outputs()
                );
            }

            return new FlowExecutionResult(
                    executionId,
                    FlowStatus.SUCCESS,
                    nodeResults,
                    null
            );

        } catch (Exception e) {
            return new FlowExecutionResult(
                    executionId,
                    FlowStatus.FAILED,
                    nodeResults,
                    e.getMessage()
            );
        }
    }

    private List<NodeDefinition> safeNodes(FlowDefinition flow) {
        return flow.nodes() == null ? List.of() : flow.nodes();
    }

    private List<EdgeDefinition> safeEdges(FlowDefinition flow) {
        return flow.edges() == null ? List.of() : flow.edges();
    }

    private Map<String, Object> resolveInputs(
            NodeDefinition node,
            List<EdgeDefinition> edges,
            Map<String, Map<String, Object>> context
    ) {
        Map<String, Object> inputs = new LinkedHashMap<>();

        List<InputPort> inputPorts = node.inputPorts() == null
                ? List.of()
                : node.inputPorts();

        Map<String, InputPort> inputPortMap = new HashMap<>();

        for (InputPort port : inputPorts) {
            inputPortMap.put(port.code(), port);
        }

        for (EdgeDefinition edge : edges) {
            if (!Objects.equals(edge.targetNodeId(), node.id())) {
                continue;
            }

            Map<String, Object> sourceOutputs = context.get(edge.sourceNodeId());

            if (sourceOutputs == null) {
                continue;
            }

            Object value = sourceOutputs.get(edge.sourcePort());
            String targetPort = edge.targetPort();

            if (targetPort == null) {
                continue;
            }

            InputPort inputPort = inputPortMap.get(targetPort);
            boolean multi = inputPort != null && inputPort.multi();

            if (multi) {
                Object current = inputs.get(targetPort);

                List<Object> list = new ArrayList<>();

                if (current instanceof List<?> currentList) {
                    list.addAll(currentList);
                } else if (current != null) {
                    list.add(current);
                }

                list.add(value);

                inputs.put(targetPort, list);
            } else {
                inputs.put(targetPort, value);
            }
        }

        return inputs;
    }

    private List<NodeDefinition> topologicalSort(
            List<NodeDefinition> nodes,
            List<EdgeDefinition> edges
    ) {
        Map<String, NodeDefinition> nodeMap = new LinkedHashMap<>();
        Map<String, Integer> inDegree = new LinkedHashMap<>();
        Map<String, List<String>> graph = new LinkedHashMap<>();

        for (NodeDefinition node : nodes) {
            nodeMap.put(node.id(), node);
            inDegree.put(node.id(), 0);
            graph.put(node.id(), new ArrayList<>());
        }

        for (EdgeDefinition edge : edges) {
            String source = edge.sourceNodeId();
            String target = edge.targetNodeId();

            if (!graph.containsKey(source) || !inDegree.containsKey(target)) {
                continue;
            }

            graph.get(source).add(target);
            inDegree.put(target, inDegree.get(target) + 1);
        }

        Queue<String> queue = new LinkedList<>();

        for (Map.Entry<String, Integer> entry : inDegree.entrySet()) {
            if (entry.getValue() == 0) {
                queue.offer(entry.getKey());
            }
        }

        List<NodeDefinition> sorted = new ArrayList<>();

        while (!queue.isEmpty()) {
            String current = queue.poll();
            sorted.add(nodeMap.get(current));

            for (String next : graph.getOrDefault(current, List.of())) {
                int degree = inDegree.get(next) - 1;
                inDegree.put(next, degree);

                if (degree == 0) {
                    queue.offer(next);
                }
            }
        }

        if (sorted.size() != nodes.size()) {
            throw new IllegalStateException("流程存在循环依赖");
        }

        return sorted;
    }
}
```

```java
        if (outputsObj instanceof Map<?, ?> map) {
            map.forEach((key, value) -> outputs.put(String.valueOf(key), value));
        } else if (config.containsKey("value")) {
            outputs.put("value", config.get("value"));
        }

        return outputs;
    }
```

## 3. `CalculateNodeExecutor.java`

计算节点。

这个 Demo 里支持：

- `SUM`
- `MULTIPLY`

它会把所有输入端口里的数字拿出来计算。

配置示例：

```json
{
  "operation": "MULTIPLY"
}
```

如果输入：

```json
{
  "price": 100,
  "quantity": 3
}
```

输出：

```json
{
  "result": 300,
  "message": "operation=MULTIPLY, inputs={price=100, quantity=3}"
}
```

```java
package com.example.flowdemo.executor;

import com.example.flowdemo.engine.NodeExecutionContext;
import com.example.flowdemo.engine.NodeExecutor;
import com.example.flowdemo.model.NodeResult;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.Collection;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@Component
public class CalculateNodeExecutor implements NodeExecutor {

    @Override
    public String supportType() {
        return "CALCULATE";
    }

    @Override
    public NodeResult execute(NodeExecutionContext context) {
        try {
            Map<String, Object> config = context.node().config() == null
                    ? Map.of()
                    : context.node().config();

            String operation = String.valueOf(
                    config.getOrDefault("operation", "SUM")
            ).toUpperCase();

            List<Double> numbers = new ArrayList<>();
            collectNumbers(context.inputs().values(), numbers);

            double result;

            if (numbers.isEmpty()) {
                result = 0;
            } else if ("MULTIPLY".equals(operation)) {
                result = numbers.stream()
                        .reduce(1.0, (a, b) -> a * b);
            } else {
                result = numbers.stream()
                        .mapToDouble(Double::doubleValue)
                        .sum();
            }

            Map<String, Object> outputs = new LinkedHashMap<>();
            outputs.put("result", result);
            outputs.put(
                    "message",
                    "operation=" + operation + ", inputs=" + context.inputs()
            );

            return NodeResult.success(outputs);

        } catch (Exception e) {
            return NodeResult.fail(e.getMessage());
        }
    }

    private void collectNumbers(Collection<Object> values, List<Double> numbers) {
        for (Object value : values) {
            collectNumber(value, numbers);
        }
    }

    private void collectNumber(Object value, List<Double> numbers) {
        if (value instanceof Collection<?> collection) {
            for (Object item : collection) {
                collectNumber(item, numbers);
            }
            return;
        }

        if (value == null) {
            return;
        }

        try {
            numbers.add(Double.parseDouble(value.toString()));
        } catch (NumberFormatException ignored) {
        }
    }
}
```

```java
        return new InputPort(code, name, dataType, true, false);
    }

    private OutputPort output(String code, String name, String dataType) {
        return new OutputPort(code, name, dataType);
    }
```

```vue
<script setup>
import { onMounted, ref, markRaw } from 'vue'
import { VueFlow } from '@vue-flow/core'
import axios from 'axios'
import FlowNode from './components/FlowNode.vue'

const nodeTypes = {
  flowNode: markRaw(FlowNode)
}

const nodes = ref([])
const edges = ref([])
const result = ref(null)
const message = ref('')

onMounted(() => {
  loadDemo()
})

async function loadDemo() {
  try {
    const response = await axios.get('/api/flows/demo')
    applyFlow(response.data)
    message.value = '示例流程加载成功'
  } catch (error) {
    message.value = '加载失败，请先启动后端：' + error.message
  }
}

function applyFlow(data) {
  nodes.value = (data.nodes || []).map(node => {
    return {
      id: node.id,
      type: 'flowNode',
      draggable: true,
      position: node.position || { x: 0, y: 0 },
      data: {
        label: node.name,
        backendType: node.type,
        config: node.config || {},
        inputPorts: node.inputPorts || [],
        outputPorts: node.outputPorts || [],
        outputs: null,
        status: null,
        errorMessage: null
      }
    }
  })

  edges.value = (data.edges || []).map(edge => {
    return {
      id: edge.id,
      source: edge.sourceNodeId,
      target: edge.targetNodeId,
      sourceHandle: edge.sourcePort,
      targetHandle: edge.targetPort
    }
  })
}

function onConnect(params) {
  const edge = {
    id: 'edge_' + Date.now(),
    source: params.source,
    target: params.target,
    sourceHandle: params.sourceHandle,
    targetHandle: params.targetHandle
  }

  edges.value = [...edges.value, edge]
}

async function executeFlow() {
  try {
    const payload = buildPayload()

    const response = await axios.post('/api/flows/execute', payload)
    result.value = response.data

    nodes.value = nodes.value.map(node => {
      const nodeResult = response.data.nodeResults?.[node.id]

      return {
        ...node,
        data: {
          ...node.data,
          status: nodeResult?.status || null,
          outputs: nodeResult?.outputs || null,
          errorMessage: nodeResult?.errorMessage || null
        }
      }
    })

    message.value = '执行完成：' + response.data.status
  } catch (error) {
    message.value = '执行失败：' + error.message
  }
}

function buildPayload() {
  return {
    flowId: 'demo_flow',
    name: '前端提交流程',
    nodes: nodes.value.map(node => {
      return {
        id: node.id,
        type: node.data.backendType,

        position: node.position,
        config: node.data.config,
        inputPorts: node.data.inputPorts,
        outputPorts: node.data.outputPorts
      }
    }),
    edges: edges.value.map(edge => {
      return {
        id: edge.id,
        sourceNodeId: edge.source,
        sourcePort: edge.sourceHandle ?? 'value',
        targetNodeId: edge.target,
        targetPort: edge.targetHandle ?? 'value'
      }
    })
  }
}
</script>
```

你的目标可以抽象成：

> 方法返回值自动变成节点输出端口。  
> 前端左侧展示这些节点，可以拖入/添加到画布，自由连线执行。

# 一、最终效果

你可以这样写一个计算方法：

```java
@Service
public class DemoCalcNodes {

    @FlowNode(
            code = "multiplyPriceQuantity",
            name = "价格数量相乘",
            category = "计算",
            description = "价格 * 数量",
            outputs = {
                    @FlowOutput(code = "result", name = "计算结果", dataType = "NUMBER"),
                    @FlowOutput(code = "message", name = "计算信息", dataType = "STRING")
            }
    )
    public Map<String, Object> multiplyPriceQuantity(
            @FlowInput(value = "price", name = "价格") double price,
            @FlowInput(value = "quantity", name = "数量") int quantity
    ) {
        double result = price * quantity;

        Map<String, Object> outputs = new LinkedHashMap<>();
        outputs.put("result", result);
        outputs.put("message", "price * quantity = " + result);

        return outputs;
    }
}
```

启动后：

- 自动注册为一个节点：`价格数量相乘`
- 左侧节点库会显示它
- 前端可以添加它
- 输入端口自动是：

```text
price
quantity
```

- 输出端口自动是：

```text
result
message
```

然后你可以自由连线：

```text
手工输入价格 -> 价格数量相乘
JSON输入数量 -> 价格数量相乘
价格数量相乘 -> 输出节点
```

# 二、整体设计

核心思路：

```text
@FlowNode 方法
   ↓
启动时扫描
   ↓
生成节点模板 NodeTemplate
   ↓
放入节点仓库 FlowNodeRegistry
   ↓
前端从 /api/node-templates 获取左侧节点
   ↓
用户添加节点到画布
   ↓
节点实例类型 = METHOD
配置里保存 methodCode
   ↓
后端执行时由 MethodNodeExecutor 找到对应方法
   ↓
反射调用方法
   ↓
返回输入输出结果
```

核心模型：

```text
方法参数 -> 输入端口
方法返回值 -> 输出端口
方法本身 -> 节点执行逻辑
```

```java
import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.CopyOnWriteArrayList;

@Component
public class FlowNodeRegistry {

    private final Map<String, MethodNodeDefinition> methodNodes = new ConcurrentHashMap<>();

    private final List<NodeTemplate> templates = new CopyOnWriteArrayList<>();

    public void register(MethodNodeDefinition definition, NodeTemplate template) {
        if (methodNodes.containsKey(definition.code())) {
            throw new IllegalStateException("重复的节点代码: " + definition.code());
        }

        methodNodes.put(definition.code(), definition);
        templates.add(template);
    }

    public MethodNodeDefinition getMethodNode(String code) {
        return methodNodes.get(code);
    }

    public List<NodeTemplate> getTemplates() {
        return templates.stream()
                .sorted(
                        Comparator.comparing(NodeTemplate::category)
                                .thenComparing(NodeTemplate::name)
                )
                .toList();
    }
}
```

## `FlowNodeScanner.java`

路径：

```text
backend/src/main/java/com/example/flowdemo/node/FlowNodeScanner.java
```

这个类会在 Spring 启动完成后扫描所有 Bean 的方法。

只要方法上有 `@FlowNode`，就自动注册成节点。

```java
package com.example.flowdemo.node;

import com.example.flowdemo.annotation.FlowInput;
import com.example.flowdemo.annotation.FlowNode;
import com.example.flowdemo.annotation.FlowOutput;
import com.example.flowdemo.model.InputPort;
import com.example.flowdemo.model.OutputPort;
import org.springframework.aop.framework.Advised;
import org.springframework.aop.support.AopUtils;
import org.springframework.beans.factory.SmartInitializingSingleton;
import org.springframework.context.ApplicationContext;
import org.springframework.core.DefaultParameterNameDiscoverer;
import org.springframework.core.ParameterNameDiscoverer;
import org.springframework.core.annotation.AnnotationUtils;
import org.springframework.stereotype.Component;
import org.springframework.util.ReflectionUtils;
import org.springframework.util.StringUtils;

import java.lang.reflect.Method;
import java.lang.reflect.Parameter;
import java.lang.reflect.RecordComponent;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collection;
import java.util.List;
import java.util.Map;

@Component
public class FlowNodeScanner implements SmartInitializingSingleton {

    private final ApplicationContext applicationContext;

    private final FlowNodeRegistry registry;

    private final ParameterNameDiscoverer parameterNameDiscoverer =
            new DefaultParameterNameDiscoverer();

    public FlowNodeScanner(
            ApplicationContext applicationContext,
            FlowNodeRegistry registry
    ) {
        this.applicationContext = applicationContext;
        this.registry = registry;
    }

    @Override
    public void afterSingletonsInstantiated() {
        String[] beanNames = applicationContext.getBeanDefinitionNames();

        for (String beanName : beanNames) {
            Object bean;

            try {
                bean = applicationContext.getBean(beanName);
            } catch (Exception e) {
                continue;
            }

            Object target = resolveTarget(bean);
            Class<?> targetClass = target.getClass();

            ReflectionUtils.doWithMethods(targetClass, method -> {
                FlowNode annotation = AnnotationUtils.findAnnotation(method, FlowNode.class);

                if (annotation == null) {
                    return;
                }

                registerMethodNode(bean, targetClass, method, annotation);
            });
        }
    }

    private Object resolveTarget(Object bean) {
        try {
            if (AopUtils.isAopProxy(bean) && bean instanceof Advised advised) {
                Object target = advised.getTargetSource().getTarget();

                if (target != null) {
                    return target;
                }
            }
        } catch (Exception ignored) {
        }

        return bean;
    }

    private void registerMethodNode(
            Object bean,
            Class<?> targetClass,
            Method method,
            FlowNode annotation
    ) {
        String code = StringUtils.hasText(annotation.code())
                ? annotation.code()
                : method.getName();

        List<MethodInputParam> inputParams = new ArrayList<>();
        List<InputPort> inputPorts = new ArrayList<>();

        Parameter[] parameters = method.getParameters();
        String[] parameterNames = parameterNameDiscoverer.getParameterNames(method);

        for (int i = 0; i < parameters.length; i++) {
            Parameter parameter = parameters[i];

            FlowInput inputAnnotation = parameter.getAnnotation(FlowInput.class);

            String paramCode;

            if (inputAnnotation != null && StringUtils.hasText(inputAnnotation.value())) {
                paramCode = inputAnnotation.value();
            } else if (parameterNames != null
                    && parameterNames.length > i
                    && StringUtils.hasText(parameterNames[i])) {
                paramCode = parameterNames[i];
            } else {
                paramCode = "arg" + i;
            }

            String paramName = inputAnnotation != null && StringUtils.hasText(inputAnnotation.name())
                    ? inputAnnotation.name()
                    : paramCode;

            boolean required = inputAnnotation == null || inputAnnotation.required();

            boolean multi = inputAnnotation != null
                    ? inputAnnotation.multi()
                    : Collection.class.isAssignableFrom(parameter.getType());

            inputParams.add(
                    new MethodInputParam(
                            paramCode,
                            paramName,
                            parameter.getType(),
                            parameter.getParameterizedType(),
                            required
                    )
            );

            inputPorts.add(
                    new InputPort(
                            paramCode,
                            paramName,
                            dataType(parameter.getType()),
                            required,
                            multi
                    )
            );
        }

        List<OutputPort> outputPorts = buildOutputPorts(method, annotation);

        Method invokeMethod = ReflectionUtils.findMethod(
                bean.getClass(),
                method.getName(),
                method.getParameterTypes()
        );

        if (invokeMethod == null) {
            invokeMethod = method;
        }

        ReflectionUtils.makeAccessible(invokeMethod);

        MethodNodeDefinition definition = new MethodNodeDefinition(
                code,
                bean,
                invokeMethod,
                inputParams,
                outputPorts
        );

        NodeTemplate template = new NodeTemplate(
                code,
                annotation.name(),
                annotation.category(),
                annotation.description(),
                "METHOD",
                Map.of("methodCode", code),
                inputPorts,
                outputPorts
        );

        registry.register(definition, template);
    }

    private List<OutputPort> buildOutputPorts(Method method, FlowNode annotation) {
        if (annotation.outputs().length > 0) {
            return Arrays.stream(annotation.outputs())
                    .map(output -> new OutputPort(
                            output.code(),
                            StringUtils.hasText(output.name()) ? output.name() : output.code(),
                            output.dataType()
                    ))
                    .toList();
        }

        Class<?> returnType = method.getReturnType();

        if (returnType == void.class || returnType == Void.class) {
            return List.of();
        }

        if (returnType.isRecord()) {
            RecordComponent[] components = returnType.getRecordComponents();

            return Arrays.stream(components)
                    .map(component -> new OutputPort(
                            component.getName(),
                            component.getName(),
                            dataType(component.getType())
                    ))
                    .toList();
        }

        if (Map.class.isAssignableFrom(returnType)) {
            return List.of(
                    new OutputPort(
                            "result",
                            "结果",
                            "OBJECT"
                    )
            );
        }

        return List.of(
                new OutputPort(
                        "result",
                        "结果",
                        dataType(returnType)
                )
        );
    }

    private String dataType(Class<?> type) {
        if (type == int.class
                || type == long.class
                || type == double.class
                || type == float.class
                || type == short.class
                || type == byte.class
                || Number.class.isAssignableFrom(type)) {
            return "NUMBER";
        }

        if (type == String.class || CharSequence.class.isAssignableFrom(type)) {
            return "STRING";
        }

        if (type == boolean.class || type == Boolean.class) {
            return "BOOLEAN";
        }

        if (type.isArray() || Collection.class.isAssignableFrom(type)) {
            return "ARRAY";
        }

        return "OBJECT";
    }
}
```

## `MethodNodeExecutor.java`

路径：

```text
backend/src/main/java/com/example/flowdemo/executor/MethodNodeExecutor.java
```

所有 `type = METHOD` 的节点都由它执行。

它会根据节点配置里的 `methodCode` 找到对应方法，然后反射调用。

```java
package com.example.flowdemo.executor;

import com.example.flowdemo.engine.NodeExecutionContext;
import com.example.flowdemo.engine.NodeExecutor;
import com.example.flowdemo.model.NodeResult;
import com.example.flowdemo.model.OutputPort;
import com.example.flowdemo.node.FlowNodeRegistry;
import com.example.flowdemo.node.MethodInputParam;
import com.example.flowdemo.node.MethodNodeDefinition;
import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.JavaType;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.stereotype.Component;

import java.lang.reflect.InvocationTargetException;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@Component
public class MethodNodeExecutor implements NodeExecutor {

    private final FlowNodeRegistry registry;

    private final ObjectMapper objectMapper;

    public MethodNodeExecutor(
            FlowNodeRegistry registry,
            ObjectMapper objectMapper
    ) {
        this.registry = registry;
        this.objectMapper = objectMapper;
    }

    @Override
    public String supportType() {
        return "METHOD";
    }

    @Override
    public NodeResult execute(NodeExecutionContext context) {
        try {
            Map<String, Object> config = context.node().config() == null
                    ? Map.of()
                    : context.node().config();

            String methodCode = String.valueOf(config.get("methodCode"));

            MethodNodeDefinition definition = registry.getMethodNode(methodCode);

            if (definition == null) {
                return NodeResult.fail("找不到方法节点: " + methodCode);
            }

            Map<String, Object> inputs = mergeInputs(context);

            List<Object> args = new ArrayList<>();

            for (MethodInputParam param : definition.inputParams()) {
                Object value = inputs.get(param.code());

                if (value == null) {
                    if (param.required()) {
                        if (param.rawType().isPrimitive()) {
                            value = defaultPrimitive(param.rawType());
                        } else {
                            return NodeResult.fail("缺少输入: " + param.code());
                        }
                    }
                }

                args.add(convertValue(value, param));
            }

            Object result = definition.method().invoke(
                    definition.bean(),
                    args.toArray()
            );

            Map<String, Object> outputs = buildOutputs(definition, result);

            return NodeResult.success(outputs);

        } catch (InvocationTargetException e) {
            return NodeResult.fail(e.getTargetException().getMessage());
        } catch (Exception e) {
            return NodeResult.fail(e.getMessage());
        }
    }

    private Map<String, Object> mergeInputs(NodeExecutionContext context) {
        Map<String, Object> merged = new LinkedHashMap<>();

        if (context.inputs() != null) {
            merged.putAll(context.inputs());
        }

        Map<String, Object> config = context.node().config() == null
                ? Map.of()
                : context.node().config();

        Object inputValuesObj = config.get("inputValues");

        if (inputValuesObj instanceof Map<?, ?> map) {
            map.forEach((key, value) -> {
                merged.putIfAbsent(String.valueOf(key), value);
            });
        }

        return merged;
    }

    private Object convertValue(Object value, MethodInputParam param) {
        if (value == null) {
            if (param.rawType().isPrimitive()) {
                return defaultPrimitive(param.rawType());
            }

            return null;
        }

        JavaType javaType = objectMapper.constructType(param.genericType());

        return objectMapper.convertValue(value, javaType);
    }

    private Object defaultPrimitive(Class<?> type) {
        if (type == boolean.class) {
            return false;
        }

        if (type == int.class) {
            return 0;
        }

        if (type == long.class) {
            return 0L;
        }

        if (type == double.class) {
            return 0.0D;
        }

        if (type == float.class) {
            return 0.0F;
        }

        if (type == short.class) {
            return (short) 0;
        }

        if (type == byte.class) {
            return (byte) 0;
        }

        if (type == char.class) {
            return '\0';
        }

        return null;
    }

    private Map<String, Object> buildOutputs(
            MethodNodeDefinition definition,
            Object result
    ) {
        Map<String, Object> outputs = new LinkedHashMap<>();

        if (result == null) {
            return outputs;
        }

        List<OutputPort> ports = definition.outputPorts();

        if (ports.isEmpty()) {
            return outputs;
        }

        if (result instanceof Map<?, ?> map) {
            Map<String, Object> converted = new LinkedHashMap<>();

            map.forEach((key, value) -> converted.put(String.valueOf(key), value));

            if (ports.size() == 1
                    && "result".equals(ports.get(0).code())
                    && !converted.containsKey("result")) {
                outputs.put("result", converted);
            } else {
                for (OutputPort port : ports) {
                    if (converted.containsKey(port.code())) {
                        outputs.put(port.code(), converted.get(port.code()));
                    }
                }

                if (outputs.isEmpty()) {
                    outputs.putAll(converted);
                }
            }

            return outputs;
        }

        if (ports.size() == 1 && isSimple(result)) {
            outputs.put(ports.get(0).code(), result);
            return outputs;
        }

        try {
            Map<String, Object> map = objectMapper.convertValue(
                    result,
                    new TypeReference<Map<String, Object>>() {
                    }
            );

            for (OutputPort port : ports) {
                if (map.containsKey(port.code())) {
                    outputs.put(port.code(), map.get(port.code()));
                }
            }

            if (outputs.isEmpty() && ports.size() == 1) {
                outputs.put(ports.get(0).code(), result);
            }

        } catch (Exception e) {
            outputs.put(ports.get(0).code(), result);
        }

        return outputs;
    }

    private boolean isSimple(Object value) {
        return value instanceof Number
                || value instanceof CharSequence
                || value instanceof Boolean
                || value instanceof Character
                || value instanceof java.util.UUID
                || value instanceof java.time.temporal.TemporalAccessor;
    }
}
```

```vue
  const map = new Map()

    if (!map.has(category)) {
      map.set(category, [])
    }

    map.get(category).push(template)
  }

  return Array.from(map.entries()).map(([category, items]) => {
    return {
      category,
      items
    }
  })
})

function applyFlow(data) {
  nodes.value = (data.nodes || []).map(node => {
    return {
      id: node.id,
      type: 'flowNode',
      draggable: true,
      position: node.position || { x: 0, y: 0 },
      data: {
        label: node.name,
        backendType: node.type,
        config: node.config || {},
        inputPorts: node.inputPorts || [],
        outputPorts: node.outputPorts || [],
        outputs: null,
        status: null,
        errorMessage: null
      }
    }
  })

  edges.value = (data.edges || []).map(edge => {
    return {
      id: edge.id,
      source: edge.sourceNodeId,
      target: edge.targetNodeId,
      sourceHandle: edge.sourcePort,
      targetHandle: edge.targetPort
    }
  })
}

function addNode(template) {
  nodeSeq++

  const id = `${template.code}_${nodeSeq}`

  const node = {
    id,
    type: 'flowNode',
    draggable: true,
    position: {
      x: 160 + nodeSeq * 50,
      y: 120 + nodeSeq * 50
    },
    data: {
      label: template.name,
      backendType: template.nodeType,
      config: JSON.parse(JSON.stringify(template.defaultConfig || {})),
      inputPorts: template.inputPorts || [],
      outputPorts: template.outputPorts || [],
      outputs: null,
      status: null,
      errorMessage: null
    }
  }

  nodes.value = [...nodes.value, node]
}

function onConnect(params) {
  const edge = {
    id: 'edge_' + Date.now(),
    source: params.source,
    target: params.target,
    sourceHandle: params.sourceHandle,
    targetHandle: params.targetHandle
  }

  edges.value = [...edges.value, edge]
}

async function executeFlow() {
  try {
    const payload = buildPayload()

    const response = await axios.post('/api/flows/execute', payload)
    result.value = response.data

    nodes.value = nodes.value.map(node => {
      const nodeResult = response.data.nodeResults?.[node.id]

      return {
        ...node,
        data: {
          ...node.data,
          status: nodeResult?.status || null,
          outputs: nodeResult?.outputs || null,
          errorMessage: nodeResult?.errorMessage || null
        }
      }
    })

    message.value = '执行完成：' + response.data.status
  } catch (error) {
    message.value = '执行失败：' + error.message
  }
}

function buildPayload() {
  return {

        sourcePort: edge.sourceHandle ?? 'value',

        targetPort: edge.targetHandle ?? 'value'

    })
  }
}
```

# 十三、如何包装你现有的计算方法

假设你现在已经有一个方法：

```java
@Service
public class OrderService {

    public OrderAmountResult calculateOrderAmount(Order order) {
        // 现有逻辑
    }
}
```

你可以这样做。

---

## 方式一：直接在现有方法上加注解

如果这个方法本身就可以作为节点：

```java
@Service
public class OrderService {

    @FlowNode(
            code = "calculateOrderAmount",
            name = "计算订单金额",
            category = "订单"
    )
    public OrderAmountResult calculateOrderAmount(
            @FlowInput(value = "order", name = "订单") Order order
    ) {
        // 现有逻辑
        return new OrderAmountResult(...);
    }
}
```

如果 `OrderAmountResult` 是一个 record：

```java
public record OrderAmountResult(
        double totalAmount,
        double discountAmount,
        double payAmount
) {
}
```

那么节点输出端口会自动变成：

```text
totalAmount
discountAmount
payAmount
```

---

## 方式二：加一个包装方法

如果你不想污染原有业务方法，可以写一个包装类。

```java
@Service
public class OrderFlowNodes {

    private final OrderService orderService;

    public OrderFlowNodes(OrderService orderService) {
        this.orderService = orderService;
    }

    @FlowNode(
            code = "calculateOrderAmount",
            name = "计算订单金额",
            category = "订单"
    )
    public OrderAmountResult calculateOrderAmount(
            @FlowInput(value = "order", name = "订单") Order order
    ) {
        return orderService.calculateOrderAmount(order);
    }
}
```

这是我最推荐的方式。

原因：

- 业务方法保持干净
- 节点元数据单独管理
- 可以做参数适配
- 可以做结果适配
- 不会影响原有业务调用

# 十六、关于方法参数名的注意事项

如果你这样写：

```java
public double multiply(double price, int quantity)
```

没有加 `@FlowInput`，系统会尝试用参数名：

```text
price
quantity
```

但前提是编译时保留参数名。

所以建议：

```xml
<configuration>
    <parameters>true</parameters>
</configuration>
```

或者显式写：

```java
public double multiply(
        @FlowInput("price") double price,
        @FlowInput("quantity") int quantity
)
```

显式写更稳定。

### USER
这些节点之间数据传递都是保存在flowcontext中吗？比如一个flow   输入节点a-计算节点a-计算节点b-输出节点c 。我想在计算节点a 上加一个输出节点d 查看计算节点a的结果。可以吗？

### ASSISTANT
可以，而且这正是这种节点引擎很典型的用法：**在中间节点后面挂一个观察/调试输出节点，查看中间结果**。

---

# 1. 节点之间的数据是不是保存在 FlowContext 中？

是的，思想上就是：

> 每个节点执行完后，把自己的输出结果写入一个统一的执行上下文。  
> 下游节点执行前，根据连线从上下文中读取上游节点的输出。

在前面那个 Demo 里，`DefaultFlowEngine` 中其实已经有这个上下文了：

```java
Map<String, Map<String, Object>> context = new HashMap<>();
```

结构大概是：

```json
{
  "输入节点a": {
    "output1": "xxx"
  },
  "计算节点a": {
    "result": 100,
    "message": "xxx"
  },
  "计算节点b": {
    "result": 90
  },
  "输出节点c": {
    "result": 90
  },
  "输出节点d": {
    "result": 100
  }
}
```

也就是说，节点之间不是直接调用：

```text
计算节点a 直接传值给 计算节点b
```

而是：

```text
计算节点a 执行完
    ↓
输出写入 FlowContext
    ↓
计算节点b 从 FlowContext 读取
```

---

# 2. 你说的场景完全可以

原流程：

```text
输入节点a
   ↓
计算节点a
   ↓
计算节点b
   ↓
输出节点c
```

你想在计算节点a后面加一个输出节点d：

```text
输入节点a
   ↓
计算节点a
   ├──────────→ 输出节点d
   ↓
计算节点b
   ↓
输出节点c
```

这是完全合理的。

它对应的连线是：

```text
输入节点a.输出  -> 计算节点a.输入
计算节点a.结果  -> 计算节点b.输入
计算节点a.结果  -> 输出节点d.输入
计算节点b.结果  -> 输出节点c.输入
```

重点是：

> 一个输出端口可以连接多个下游输入端口。

所以 `计算节点a` 的同一个输出端口可以同时连：

```text
计算节点b
输出节点d
```

---

# 3. 在数据结构上怎么表示？

假设节点如下：

```text
input_a      输入节点a
calc_a       计算节点a
calc_b       计算节点b
output_c     输出节点c
output_d     输出节点d，用于查看 calc_a 结果
```

连线可以这样：

```json
[
  {
    "id": "edge_1",
    "sourceNodeId": "input_a",
    "sourcePort": "data",
    "targetNodeId": "calc_a",
    "targetPort": "data"
  },
  {
    "id": "edge_2",
    "sourceNodeId": "calc_a",
    "sourcePort": "result",
    "targetNodeId": "calc_b",
    "targetPort": "data"
  },
  {
    "id": "edge_3",
    "sourceNodeId": "calc_a",
    "sourcePort": "result",
    "targetNodeId": "output_d",
    "targetPort": "data"
  },
  {
    "id": "edge_4",
    "sourceNodeId": "calc_b",
    "sourcePort": "result",
    "targetNodeId": "output_c",
    "targetPort": "data"
  }
]
```

注意这里：

```json
edge_2
edge_3
```

它们的 `sourceNodeId` 和 `sourcePort` 都是：

```json
sourceNodeId: "calc_a",
sourcePort: "result"
```

但是目标不同：

```text
edge_2 -> calc_b
edge_3 -> output_d
```

这就实现了：

> 计算节点a 的同一个输出，同时给计算节点b和输出节点d使用。

---

# 4. 执行顺序会是什么样？

执行引擎会根据 DAG 做拓扑排序。

对于这个流程：

```text
input_a
   ↓
calc_a
   ├────→ output_d
   ↓
calc_b
   ↓
output_c
```

执行顺序通常是：

```text
1. input_a
2. calc_a
3. calc_b
4. output_d
5. output_c
```

或者：

```text
1. input_a
2. calc_a
3. output_d
4. calc_b
5. output_c
```

这取决于连线顺序和拓扑排序实现。

但无论哪种顺序，核心都是：

```text
calc_a 一定在 calc_b 和 output_d 之前执行。
```

所以 `output_d` 可以读到 `calc_a` 的结果。

---

# 5. 输出节点d会影响计算节点b吗？

不会影响。

只要 `output_d` 不参与 `calc_b` 的输入，它就只是一个旁路观察节点。

逻辑上等价于：

```text
calc_a 的结果被复制了一份给 output_d
```

不是：

```text
calc_a 的结果被 output_d 截胡了
```

因为上下文里的数据是可以被多个下游节点读取的。

例如：

```json
{
  "calc_a": {
    "result": 100
  }
}
```

`calc_b` 可以读：

```text
calc_a.result
```

`output_d` 也可以读：

```text
calc_a.result
```

互不影响。

# 7. 建议增加一种 `DEBUG_OUTPUT` 节点

现在 Demo 里已经有：

```text
OUTPUT
```

如果只是查看中间结果，我建议后续可以增加一个节点类型：

```text
DEBUG_OUTPUT
```

区别是：

| 类型 | 说明 |
|---|---|
| `OUTPUT` | 正式输出，可能代表最终业务结果 |
| `DEBUG_OUTPUT` | 调试输出，只用于查看中间结果 |

这样流程语义更清晰。

例如：

```text
计算节点a -> DEBUG_OUTPUT
计算节点b -> OUTPUT
```

# 8. 简单实现 `DEBUG_OUTPUT`

可以新增一个执行器：

```java
@Component
public class DebugOutputNodeExecutor implements NodeExecutor {

    private static final Logger log = LoggerFactory.getLogger(DebugOutputNodeExecutor.class);

    @Override
    public String supportType() {
        return "DEBUG_OUTPUT";
    }

    @Override
    public NodeResult execute(NodeExecutionContext context) {
        Map<String, Object> outputs = new LinkedHashMap<>(context.inputs());

        log.info("调试输出节点: {}, 输入数据: {}",
                context.node().name(),
                outputs);

        return NodeResult.success(outputs);
    }
}
```

# 10. 数据是否需要持久化？

分两种情况。

---

## 情况一：只是运行时传递

那么放在内存里的 `FlowContext` 就够了。

例如：

```java
Map<String, Map<String, Object>> context
```

执行完成后可以返回给前端。

---

## 情况二：需要事后查看、审计、排障

那就不能只放内存，需要持久化。

建议保存：

```text
flow_execution       流程执行记录
node_execution       节点执行记录
```

`node_execution` 里保存：

```sql
execution_id
node_id
status
input_data
output_data
error_msg
start_time
end_time
```

这样你后面可以查询：

```text
某次执行中，计算节点a的输入是什么？
计算节点a的输出是什么？
输出节点d看到的中间结果是什么？
```

# 11. 推荐你把这个上下文封装成 `FlowContext`

现在 Demo 中是：

```java
Map<String, Map<String, Object>> context
```

后续建议封装成：

```java
public class FlowContext {

    private final String executionId;

    private final Map<String, Map<String, Object>> nodeOutputs = new HashMap<>();

    public FlowContext(String executionId) {
        this.executionId = executionId;
    }

    public String getExecutionId() {
        return executionId;
    }

    public void putNodeOutputs(String nodeId, Map<String, Object> outputs) {
        nodeOutputs.put(nodeId, outputs);
    }

    public Map<String, Object> getNodeOutputs(String nodeId) {
        return nodeOutputs.get(nodeId);
    }

    public Object getNodeOutput(String nodeId, String outputCode) {
        Map<String, Object> outputs = nodeOutputs.get(nodeId);

        if (outputs == null) {
            return null;
        }

        return outputs.get(outputCode);
    }

    public Map<String, Map<String, Object>> getAll() {
        return nodeOutputs;
    }
}
```

这样执行引擎会更清晰：

```java
FlowContext context = new FlowContext(executionId);
```

节点执行器也可以拿到：

```java
context.getNodeOutput("calc_a", "result")
```

# 12. 你的例子最终可以这样理解

原始流程：

```text
输入节点a
   ↓
计算节点a
   ↓
计算节点b
   ↓
输出节点c
```

加调试输出后：

```text
输入节点a
   ↓
计算节点a
   ├────────→ 输出节点d
   ↓
计算节点b
   ↓
输出节点c
```

运行时：

```text
input_a 执行完
    ↓
写入 context["input_a"]

calc_a 执行完
    ↓
写入 context["calc_a"]

calc_b 读取 context["calc_a"]
output_d 读取 context["calc_a"]

calc_b 执行完
    ↓
写入 context["calc_b"]

output_c 读取 context["calc_b"]
```

所以答案是：

> 可以，完全可以在计算节点a后面加一个输出节点d查看中间结果。  
> 数据通过执行上下文传递，输出端口可以一对多连接多个下游节点。  
> 输出节点d不会影响原来的计算节点b，除非你把它也连到计算节点b的输入。

### USER
我需要前端左侧展示三种类型节点，然后可以新建一个流程，保存一个流程。另外，我看前端节点图示都是输入输出都是两个点，应该是一个点。

### ASSISTANT
下面把这三个需求一次补齐：

1. **左侧固定展示三类节点**：输入节点 / 计算节点 / 输出节点
2. **支持新建流程、保存流程、加载流程**
3. **节点改为每侧一个连接点**（左侧一个输入点、右侧一个输出点）

同时为了配合「一个点」，数据传递模型从「端口对端口」简化为「节点对节点 + 字段合并」，这样更直观。

---

# 一、数据传递模型调整（配合一个点）

原来：

```text
nodeA.result -> nodeB.price
```

现在改为：

```text
nodeA -> nodeB
```

执行时，`nodeB` 会把所有上游节点的输出字段**合并**成一个输入 Map，然后计算节点按字段名取参数。

例如：

```text
手工输入 {price:100}
JSON输入 {quantity:3}
        ↓ 合并
计算节点输入 = { price:100, quantity:3 }
```

这样每个节点只需要一个输入点、一个输出点。

## 7. `DefaultFlowEngine.java` 替换 `resolveInputs`

```java
private Map<String, Object> resolveInputs(
        NodeDefinition node,
        List<EdgeDefinition> edges,
        Map<String, Map<String, Object>> context
) {
    Map<String, Object> inputs = new LinkedHashMap<>();

    List<InputPort> inputPorts = node.inputPorts() == null
            ? List.of()
            : node.inputPorts();

    Map<String, InputPort> portMap = new HashMap<>();
    for (InputPort port : inputPorts) {
        portMap.put(port.code(), port);
    }

    for (EdgeDefinition edge : edges) {
        if (!Objects.equals(edge.targetNodeId(), node.id())) {
            continue;
        }

        Map<String, Object> sourceOutputs = context.get(edge.sourceNodeId());

        if (sourceOutputs == null) {
            continue;
        }

        for (Map.Entry<String, Object> entry : sourceOutputs.entrySet()) {
            String key = entry.getKey();
            InputPort port = portMap.get(key);

            if (port != null && port.multi()) {
                Object current = inputs.get(key);

                List<Object> list = new ArrayList<>();
                if (current instanceof List<?> currentList) {
                    list.addAll(currentList);
                } else if (current != null) {
                    list.add(current);
                }
                list.add(entry.getValue());

                inputs.put(key, list);
            } else {
                inputs.put(key, entry.getValue());
            }
        }
    }

    return inputs;
}
```

拓扑排序里只用到 `sourceNodeId / targetNodeId`，无需改动。

```java
package com.example.flowdemo.service;

import com.example.flowdemo.model.FlowDefinition;
import com.example.flowdemo.model.FlowSummary;
import org.springframework.stereotype.Component;

import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.UUID;
import java.util.concurrent.ConcurrentHashMap;

@Component
public class FlowStore {

    private final Map<String, FlowDefinition> flows = new ConcurrentHashMap<>();

    private final Map<String, Long> updateTimes = new ConcurrentHashMap<>();

    public FlowDefinition save(FlowDefinition flow) {
        String id = flow.flowId();

        if (id == null || id.isBlank()) {
            id = UUID.randomUUID().toString();
        }

        FlowDefinition saved = new FlowDefinition(
                id,
                flow.name(),
                flow.nodes(),
                flow.edges()
        );

        flows.put(id, saved);
        updateTimes.put(id, System.currentTimeMillis());

        return saved;
    }

    public List<FlowSummary> list() {
        return flows.values().stream()
                .map(f -> new FlowSummary(
                        f.flowId(),
                        f.name(),
                        updateTimes.getOrDefault(f.flowId(), 0L)
                ))
                .sorted(Comparator.comparingLong(FlowSummary::updateTime).reversed())
                .toList();
    }

    public FlowDefinition get(String id) {
        return flows.get(id);
    }

    public void delete(String id) {
        flows.remove(id);
        updateTimes.remove(id);
    }
}
```

# 五、一个重要说明

现在「一个点」模型下，端口字段更多是**说明性**的，真正取数靠**字段名匹配**：

- 上游输出什么字段，下游就能按字段名取什么字段
- 计算节点的方法参数名 / `@FlowInput` 值，就是它要取的字段名

所以你在编辑输入节点配置时，只要保证输出字段名和计算方法参数名一致即可，例如：

```json
{
  "outputs": { "price": 100 }
}
```

对应：

```java
@FlowInput("price") double price
```

这样整个「新建 → 搭配 → 保存 → 执行」的闭环就完整了。

## 2. `FlowNodeRegistry` 是否有 `registerTemplate`

确保你的 `FlowNodeRegistry` 是这个版本：

```java
package com.example.flowdemo.node;

import org.springframework.stereotype.Component;

import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.CopyOnWriteArrayList;

@Component
public class FlowNodeRegistry {

    private final Map<String, MethodNodeDefinition> methodNodes = new ConcurrentHashMap<>();

    private final List<NodeTemplate> templates = new CopyOnWriteArrayList<>();

    public void registerTemplate(NodeTemplate template) {
        templates.add(template);
    }

    public void registerMethodNode(MethodNodeDefinition definition, NodeTemplate template) {
        methodNodes.put(definition.code(), definition);
        templates.add(template);
    }

    public MethodNodeDefinition getMethodNode(String code) {
        return methodNodes.get(code);
    }

    public List<NodeTemplate> getTemplates() {
        return templates.stream()
                .sorted(
                        Comparator
                                .comparing(
                                        NodeTemplate::kind,
                                        Comparator.nullsLast(Comparator.naturalOrder())
                                )
                                .thenComparing(
                                        NodeTemplate::category,
                                        Comparator.nullsLast(Comparator.naturalOrder())
                                )
                                .thenComparing(
                                        NodeTemplate::name,
                                        Comparator.nullsLast(Comparator.naturalOrder())
                                )
                )
                .toList();
    }
}
```

这里我加了：

```java
Comparator.nullsLast
```

防止某些模板 `kind` 为 `null` 导致接口 500。

# 五、如果接口有数据，但前端左侧不显示

最常见原因是：

## 修改 `App.vue` 的 `loadNodeTemplates`

替换成下面这个：

```javascript
async function loadNodeTemplates() {
  try {
    const res = await axios.get('/api/flows/node-templates')

    console.log('节点模板接口返回：', res.data)

    const data = Array.isArray(res.data) ? res.data : []

    templates.value = data.map(item => {
      return {
        ...item,
        kind: item.kind || guessKind(item.nodeType, item.code)
      }
    })

    message.value = `节点库加载成功：${templates.value.length} 个节点`
  } catch (error) {
    console.error(error)
    message.value = '节点库加载失败：' + error.message
  }
}

function guessKind(nodeType, code) {
  if (!nodeType) {
    return 'CALC'
  }

  if (nodeType === 'INPUT_MANUAL' || nodeType === 'INPUT_JSON' || nodeType === 'INPUT_EXCEL') {
    return 'INPUT'
  }

  if (nodeType === 'OUTPUT' || nodeType === 'DEBUG_OUTPUT') {
    return 'OUTPUT'
  }

  return 'CALC'
}
```

这样即使后端没返回 `kind`，前端也能自动归类。

### USER
我点了一个计算节点 画布上有了 然后我删除掉，在点一个计算节点发现画布上存在两个计算节点了，而且我点击执行后，流程图的位置发生了改变，都叠在中间了。

### ASSISTANT
这个问题基本可以确定是：

> 画布内部状态和你的 `nodes` / `edges` 数据没有同步。

具体表现为：

1. 你删除节点时，只是画布内部删了，但你的 `nodes.value` 里还在。
2. 你再点一个计算节点时，代码基于旧的 `nodes.value` 添加新节点，结果被删除的节点又回来了。
3. 你拖动节点后，位置只保存在画布内部，没有同步到 `nodes.value`。
4. 点击执行后，你又用 `nodes.value` 重新渲染节点，于是所有节点位置被旧数据覆盖，看起来就叠在一起了。

解决办法是：**使用 `v-model:nodes` 和 `v-model:edges` 让画布状态与数据双向同步。**

# 一、修改 `VueFlow` 绑定

把你现在的：

```vue
<VueFlow
    :nodes="nodes"
    :edges="edges"
    :node-types="nodeTypes"
    fit-view-on-init
    @connect="onConnect"
    @node-click="onNodeClick"
/>
```

改成：

```vue
<VueFlow
    v-model:nodes="nodes"
    v-model:edges="edges"
    :node-types="nodeTypes"
    :delete-key-code="['Delete', 'Backspace']"
    :nodes-draggable="true"
    :nodes-connectable="true"
    :elements-selectable="true"
    @connect="onConnect"
    @node-click="onNodeClick"
/>
```

重点是：

```vue
v-model:nodes="nodes"
v-model:edges="edges"
```

这样：

- 拖动节点后，`nodes.value` 会同步最新位置
- 删除节点后，`nodes.value` 会同步删除
- 连线后，`edges.value` 会同步更新
- 执行后不会再把节点位置重置

# 三、添加节点时使用唯一 ID

你之前可能是用：

```javascript
id: `${template.code}_${nodeSeq}`
```

这个也能用，但为了避免删除后状态混乱，建议直接用随机 ID：

```javascript
function addNode(template) {
  const id = `${template.code}_${crypto.randomUUID()}`

  nodes.value = [
    ...nodes.value,
    {
      id,
      type: 'flowNode',
      draggable: true,
      position: {
        x: 180 + Math.random() * 200,
        y: 120 + Math.random() * 200
      },
      data: {
        label: template.name,
        backendType: template.nodeType,
        config: JSON.parse(JSON.stringify(template.defaultConfig || {})),
        inputPorts: template.inputPorts || [],
        outputPorts: template.outputPorts || [],
        outputs: null,
        status: null,
        errorMessage: null
      }
    }
  ]
}
```

这样每次添加的节点 ID 都不同，不会因为删除、重复添加造成状态错乱。

# 四、执行后不要整体重建节点

你原来执行后可能是这样：

```javascript
nodes.value = nodes.value.map(node => {
  return {
    ...node,
    data: {
      ...node.data,
      ...
    }
  }
})
```

这个写法本身没错，但如果 `nodes.value` 没同步，就会把旧位置覆盖回去。

现在改成：**只更新节点的 data，不重建整个节点对象。**

```javascript
async function executeFlow() {
  try {
    const payload = buildPayload()

    const response = await axios.post('/api/flows/execute', payload)
    result.value = response.data

    applyExecutionResult(response.data)

    message.value = '执行完成：' + response.data.status
  } catch (error) {
    message.value = '执行失败：' + error.message
  }
}

function applyExecutionResult(data) {
  const nodeResults = data.nodeResults || {}

  nodes.value.forEach(node => {
    const nodeResult = nodeResults[node.id]

    if (!nodeResult) {
      return
    }

    node.data = {
      ...node.data,
      status: nodeResult.status || null,
      outputs: nodeResult.outputs || null,
      errorMessage: nodeResult.errorMessage || null
    }
  })
}
```

这样不会影响节点位置。

```javascript
async function executeFlow() {

function applyExecutionResult(data) {
  const nodeResults = data.nodeResults || {}

  nodes.value.forEach(node => {
    const nodeResult = nodeResults[node.id]

    if (!nodeResult) {
      return
    }

    node.data = {
      ...node.data,
      status: nodeResult.status || null,
      outputs: nodeResult.outputs || null,
      errorMessage: nodeResult.errorMessage || null
    }

}
```

# 十一、为什么会发生你这个现象？

你原来的流程是：

```text
画布内部状态：删除节点 / 拖动节点
        ↓
但是 nodes.value 没更新
        ↓
点击执行
        ↓
代码又用旧的 nodes.value 渲染一次
        ↓
被删除的节点回来了
        ↓
所有节点位置也回到旧位置
```

所以看起来就是：

```text

执行后节点位置重置
```

改完后，正常效果应该是：

- 点左侧节点，画布增加一个节点
- 删除后，画布和数据同步删除
- 再点一次，只新增一个节点
- 拖动节点后，位置会保存
- 点击执行后，节点位置不会变化
- 保存流程后，再次加载，位置也还在

### USER
节点名称 描述应该可以改的 比如json类型 可以有两个输入节点 分别叫订单输入数据，库存输入数据。然后节点结果不用展示在节点中，如果展示可以加一个输出节点 类型为json 或者其他。

### ASSISTANT
可以，而且应该这么做。

你的需求我理解为两点：

1. **节点名称、描述必须支持用户修改**
   - 比如同样是 `JSON输入` 节点，可以分别改成：
     - `订单输入数据`
     - `库存输入数据`

2. **普通节点内部不要展示执行结果**
   - 计算节点、输入节点只展示：
     - 名称
     - 描述
     - 类型
     - 输入字段
     - 输出字段
     - 执行状态
   - 如果需要看结果，就给它连一个输出节点：
     - `OUTPUT`
     - `JSON_OUTPUT`
     - `DEBUG_OUTPUT`
     - 后续还可以扩展 `TABLE_OUTPUT`

# 九、为什么这样设计比较好

如果每个节点都显示结果，会有几个问题：

## 1. 画布太乱

节点里展示 JSON 会很大。

---

## 2. 中间结果太多

每个计算节点都有输出，全部展示会影响看图。

---

## 3. 不利于流程表达

流程图重点是：

```text
数据从哪来
经过哪些计算
结果输出到哪
```

而不是每个节点都展示数据。

---

## 4. 调试更灵活

想看哪个节点的结果，就给哪个节点挂一个输出节点：

```text
计算节点a -> JSON输出
```

不想看就删掉输出节点。

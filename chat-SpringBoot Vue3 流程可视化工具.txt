# 六、执行引擎设计

后端最核心的是执行引擎。

执行流程如下：

```text
1. 接收前端执行请求
2. 加载流程定义
3. 解析 DAG
4. 校验是否有环
5. 创建运行实例 runId
6. 找到入口节点
7. 按依赖关系执行节点
8. 每个节点执行前：
   - 检查是否断点
   - 检查上游节点是否完成
   - 准备输入数据
9. 执行节点
10. 保存输入输出快照
11. 发送节点状态变化事件给前端
12. 继续执行下游节点
13. 所有节点完成后流程结束
```

---

# 七、DAG 执行方式

## 1. 节点依赖关系

比如：

```text
node1 -> node3
node2 -> node3
```

那么 `node3` 必须等待 `node1` 和 `node2` 都完成。

后端可以用：

```java
Map<String, List<String>> dependencies
```

表示：

```java
node3 depends on node1, node2
```

---

## 2. 拓扑排序

执行前要确保图没有环。

可以用 Kahn 算法。

简单思路：

```text
1. 统计每个节点入度
2. 入度为 0 的节点先执行
3. 节点完成后，减少下游节点入度
4. 下游节点入度为 0 后进入可执行状态
```

---

# 八、JDK 21 虚拟线程非常适合这个场景

JDK 21 可以用虚拟线程执行节点任务。

例如：

```java
ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor();
```

适合：

- 节点中有 IO 操作
- 读取 Excel
- 读取 JSON
- 查数据库
- 调 HTTP 接口
- 文件导出

但要注意：

- 如果节点是 CPU 密集型计算，虚拟线程优势不明显
- 需要控制并发数量
- 需要注意上下文传递和异常处理

# 十二、SSE 示例

## Controller

```java
@RestController
@RequestMapping("/api/runs")
public class RunEventController {

    private final RunEventService runEventService;

    public RunEventController(RunEventService runEventService) {
        this runEventService = runEventService;
    }

    @GetMapping(value = "/{runId}/events", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public SseEmitter subscribe(@PathVariable String runId) {
        SseEmitter emitter = new SseEmitter(0L);
        runEventService.addEmitter(runId, emitter);
        return emitter;
    }
}
```

---

## 事件服务

```java
@Service
public class RunEventService {

    private final Map<String, List<SseEmitter>> emitters = new ConcurrentHashMap<>();

    public void addEmitter(String runId, SseEmitter emitter) {
        emitters.computeIfAbsent(runId, k -> new CopyOnWriteArrayList<>()).add(emitter);

        emitter.onCompletion(() -> remove(runId, emitter));
        emitter.onTimeout(() -> remove(runId, emitter));
        emitter.onError(e -> remove(runId, emitter));
    }

    public void publish(String runId, Object event) {
        List<SseEmitter> list = emitters.get(runId);

        if (list == null) {
            return;
        }

        for (SseEmitter emitter : list) {
            try {
                emitter.send(SseEmitter.event()
                        .name("node-event")
                        .data(event));
            } catch (Exception e) {
                emitter.complete();
            }
        }
    }

    private void remove(String runId, SseEmitter emitter) {
        List<SseEmitter> list = emitters.get(runId);
        if (list != null) {
            list.remove(emitter);
        }
    }
}
```

```java
public class DataSourceResolverFactory {

            resolverMap.put(resolver.type(), resolver);
```

# 十九、执行引擎伪代码

```java
@Service
public class FlowExecutionEngine {

    private final NodeExecutorFactory nodeExecutorFactory;
    private final DataSourceResolverFactory dataSourceResolverFactory;
    private final RunEventService runEventService;

    public FlowExecutionEngine(
            NodeExecutorFactory nodeExecutorFactory,
            DataSourceResolverFactory dataSourceResolverFactory,
            RunEventService runEventService
    ) {
        this.nodeExecutorFactory = nodeExecutorFactory;
        this.dataSourceResolverFactory = dataSourceResolverFactory;
        this.runEventService = runEventService;
    }

    public String run(FlowDefinition flow) {

        String runId = UUID.randomUUID().toString();

        FlowExecutionContext context = new FlowExecutionContext(runId);

        ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor();

        Map<String, NodeDefinition> nodeMap = flow.getNodes()
                .stream()
                .collect(Collectors.toMap(NodeDefinition::getId, n -> n));

        Map<String, List<String>> downstreamMap = buildDownstreamMap(flow);

        Map<String, Integer> indegreeMap = buildIndegreeMap(flow);

        Queue<String> readyNodes = new ConcurrentLinkedQueue<>();

        indegreeMap.forEach((nodeId, indegree) -> {
            if (indegree == 0) {
                readyNodes.add(nodeId);
            }
        });

        while (!readyNodes.isEmpty()) {

            String nodeId = readyNodes.poll();

            NodeDefinition node = nodeMap.get(nodeId);

            executor.submit(() -> {

                try {

                    if (node.isBreakpoint()) {
                        publish(runId, nodeId, "WAITING_BREAKPOINT");
                        // 等待恢复
                        return;
                    }

                    publish(runId, nodeId, "RUNNING");

                    Map<String, Object> inputs = resolveInputs(node, context);

                    NodeExecutionContext nodeContext = NodeExecutionContext.builder()
                            .runId(runId)
                            .nodeId(nodeId)
                            .node(node)
                            .flowContext(context)
                            .inputs(inputs)
                            .build();

                    NodeExecutor nodeExecutor = nodeExecutorFactory.getExecutor(node.getType());

                    NodeResult result = nodeExecutor.execute(nodeContext);

                    if (result.success()) {
                        context.putOutput(nodeId, result.output());
                        publish(runId, nodeId, "SUCCESS");
                    } else {
                        publish(runId, nodeId, "FAILED");
                        return;
                    }

                    List<String> downstreamNodes = downstreamMap.getOrDefault(nodeId, List.of());

                    for (String downstreamNodeId : downstreamNodes) {

                        int rest = decrementIndegree(runId, downstreamNodeId);

                        if (rest == 0) {
                            readyNodes.add(downstreamNodeId);
                        }
                    }

                } catch (Exception e) {
                    publish(runId, nodeId, "FAILED");
                }
            });
        }

        return runId;
    }

    private void publish(String runId, String nodeId, String status) {
        runEventService.publish(runId, Map.of(
                "runId", runId,
                "nodeId", nodeId,
                "status", status,
                "time", System.currentTimeMillis()
        ));
    }
}
```

# 二十、断点暂停与恢复的实现思路

断点最难的地方是：

> 执行线程不能简单阻塞整个流程，要能恢复。

有三种实现方式。

---

## 方案 1：线程等待恢复，适合单机调试

节点命中断点后，线程等待：

```java
synchronized (lock) {
    while (paused) {
        lock.wait();
    }
}
```

恢复时：

```java
synchronized (lock) {
    paused = false;
    lock.notifyAll();
}
```

优点：

- 简单
- 适合单机调试

缺点：

- 服务重启后运行状态丢失
- 不适合分布式

---

## 方案 2：状态机持久化，恢复时继续调度，推荐生产使用

命中断点后：

```text
1. 保存当前运行状态
2. 当前节点状态改为 WAITING_BREAKPOINT
3. 流程状态改为 PAUSED
4. 释放执行线程
```

用户点击继续：

```text
1. 加载 runId 状态
2. 找到等待节点
3. 重新提交执行
```

优点：

- 可持久化
- 重启可恢复
- 适合生产

缺点：

- 设计稍复杂

我更推荐这种。

---

## 方案 3：工作流引擎托管

如果你用 Flowable / Camunda，可以用 Wait State。

但你的场景是计算逻辑，所以自研更轻量。

# 二十二、节点之间传递数据的方式

有三种常见方式。

---

## 方案 1：内存传递

适合小数据。


优点：

- 快

缺点：

- 占内存
- 重启丢失

## 方案 2：快照引用

适合大数据。


优点：

```text
小数据：内存
大数据：引用
```

例如：

```java
if (dataSize < 1MB) {

    String ref = storage.save(data);
    memoryContext.put(nodeId, ref);
}
```

# 二十五、是否要用 Flowable / Camunda？

这是很多人会纠结的问题。

---

## 适合用 Flowable / Camunda 的场景

如果你有：

- 审批流
- 人工任务
- 候选人 / 候选组
- 会签
- 驳回
- 转办
- 委派
- 复杂业务状态流转
- 流程历史追溯
- BPMN 标准

那可以用：

```text
Flowable
Camunda
```

---

## 不太适合你当前需求的原因

你的需求是：

- 计算节点
- 数据输入节点
- Excel / JSON 数据源
- 断点调试
- 当前执行节点高亮
- 计算流水线

这类需求用 BPMN 会比较别扭。

比如：

- 节点输入输出数据配置不天然
- 断点调试不灵活
- 计算节点扩展要自己包装
- BPMN 图形和你要的 DAG 编辑体验不完全一致

所以：

> 如果你没有审批流需求，优先自研轻量 DAG 引擎。

# 三十一、关键难点与解决方案

## 难点 1：断点恢复

推荐：

```text
节点执行前检查断点
命中断点后保存运行状态
前端进入暂停态
恢复时重新调度当前节点
```

不要用长时间阻塞线程的方式做生产系统。

---

## 难点 2：并行节点执行顺序

用 DAG 入度控制：

```text
入度为 0 可执行
上游完成后下游入度减一
入度为 0 后进入执行队列
```

---

## 难点 3：节点数据来源不同

抽象成：

```text
DataSourceResolver
```

不要让节点执行器关心数据来自哪里。

节点只拿：

```java
Map<String, Object> inputs
```

---

## 难点 4：数据量大

不要全部放内存。

使用：

```text
快照引用
文件存储
分页读取
流式处理
```

Excel 用 EasyExcel 流式读取。

---

## 难点 5：执行状态实时同步

推荐：

```text
SSE
```

简单可靠。

# 三十二、一个完整执行流程示例

假设流程如下：

```text
Excel输入 -> 数据清洗 -> 计算金额 -> 输出结果
```

用户点击运行。

后端：

```text
1. 创建 runId
2. 流程状态 RUNNING
3. 执行 Excel输入节点
4. 推送节点 RUNNING
5. Excel节点成功
6. 推送节点 SUCCESS
7. 数据清洗节点开始
8. 命中断点
9. 推送 WAITING_BREAKPOINT
10. 流程状态 PAUSED
11. 前端橙色高亮数据清洗节点
12. 用户点击继续
13. 数据清洗节点继续执行
14. 计算金额节点执行
15. 输出结果节点执行
16. 流程状态 SUCCESS
17. 前端全部绿色
```

# 三十四、简单说：你应该怎么做

你可以按这个顺序做：

## 第一步：先做一个最小画布

用 Vue Flow 实现：

- 拖节点
- 连线
- 删除节点
- 删除连线
- 保存为 JSON

---

## 第二步：后端能解析这个 JSON

实现：

- 保存流程定义
- 查询流程定义
- 校验 DAG 是否有环

---

## 第三步：实现顺序执行引擎

先不要并行。

按照拓扑顺序执行节点。

---

## 第四步：实现 SSE 状态推送

每个节点状态变化都推给前端。

前端高亮当前节点。

---

## 第五步：实现断点

节点命中断点后暂停。

前端提供继续按钮。

---

## 第六步：实现数据源

支持：

- JSON 输入
- Excel 输入
- 上一节点输出

---

## 第七步：实现节点输入输出快照

点击节点可以查看：

- 输入
- 输出
- 日志
- 错误
